# Cloudflare Tunnel GUI

**터미널 없이 Cloudflare Tunnel을 관리하는 윈도우 데스크톱 앱.**

내 PC나 라즈베리파이에서 돌아가는 웹 서버를, 공유기 포트 포워딩이나 공인 IP 없이
`https://내도메인.com` 으로 바로 열어주는 도구입니다. `cloudflared tunnel create` →
`route dns` → `config.yml` 편집 → `tunnel run` 으로 이어지는 과정을 화면에서 클릭 몇 번으로 끝냅니다.

## 이런 분께

- 집에 있는 PC나 라즈베리파이로 **개인 서버를 운영**하고 싶은 분
- 공유기 설정(포트 포워딩·DDNS)을 건드리고 싶지 않은 분
- `cloudflared` 명령어를 매번 찾아보기 번거로운 분
- 라즈베리파이를 **Railway/Vercel처럼** 쓰고 싶은 분 — 원격 접속, Git 클론, 실행, 도메인 연결까지 한 화면에서

## 핵심 특징

**앱을 꺼도 서버는 계속 돌아갑니다.**
GUI는 프로세스를 소유하지 않습니다. 터널과 서버는 대상 머신에서 독립 프로세스로 실행되고,
앱은 PID 파일과 로그를 읽어 상태만 보여줍니다. 창을 닫아도, 앱을 재시작해도, SSH가 끊겼다
다시 붙어도 실행 중이던 것은 그대로 살아 있고 화면에 이어서 표시됩니다.

**한 터널에 여러 서비스.**
터널 하나에 서브도메인(라우트)을 여러 개 붙여 각각 다른 로컬 포트로 보낼 수 있습니다.
`blog.example.com → :3000`, `api.example.com → :8000` 처럼요. 터널 토글과 각 서버 토글은 서로 독립입니다.

**도커 컴포즈 지원.**
서버 종류를 "도커 컴포즈"로 고르면 `docker compose up --build -d` / `down` 으로 시작·정지하고,
`docker compose ps` 로 실제 실행 여부를 판정합니다.

**원격도 같은 화면에서.**
SSH로 라즈베리파이에 붙으면 로컬과 완전히 동일한 UI로 원격의 터널·서버·프로젝트를 다룹니다.

그 외: 라이트/다크 테마, 실시간 로그 뷰어, 단축키, 생성 마법사, 삭제 전 확인, 상단 `?` 안내.

## 설치

### 실행 파일로 쓰기 (권장)

`dist\Cloudflare Tunnel GUI.exe` 를 실행하면 끝입니다. 파이썬 설치가 필요 없고, 콘솔 창도 뜨지 않습니다.

### 소스로 실행하기

```bash
pip install -r requirements.txt
python -m app.main
```

파이썬 3.11 이상이 필요합니다.

## 처음 준비 (한 번만)

### 1. cloudflared 설치

앱이 `cloudflared` 명령을 대신 실행하는 구조라서, 이 프로그램은 따로 설치돼 있어야 합니다.

- **윈도우**: [공식 설치 파일](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) 또는 `winget install --id Cloudflare.cloudflared`
- **라즈베리파이/리눅스**: `.deb` 패키지 설치 (`docs/rpi-selfhost-setup.md` 참고)

PATH에 없다면 **설정 → cloudflared 경로**에 실행 파일 전체 경로를 적어주세요.

### 2. 도메인을 Cloudflare에 등록

Cloudflare 계정에 도메인이 **Active 상태**로 등록돼 있어야 합니다. 네임서버를 Cloudflare 것으로
바꾸는 과정이며, 도메인 등록업체에서 한 번만 하면 됩니다.

### 3. 로그인 (cert.pem 발급)

```bash
cloudflared tunnel login
```

브라우저가 열리고 도메인을 고르면 `~/.cloudflared/cert.pem` 이 만들어집니다.
이 파일이 있어야 터널을 만들 수 있고, 앱은 없으면 배너로 알려줍니다.
**원격 기기에서 터널을 만들 거라면 그 기기에서도** 이 명령을 실행해야 합니다.

## 화면 둘러보기

```
┌──────────────────────────────────────────────────────────────────┐
│ 대상: [🖥 이 PC        ▾]  [↻] [＋터널 생성] [프로젝트] [설정] [?] │
├──────────────────────────────────────────────────────────────────┤
│ ▼ 🖥 이 PC  2개  현재 대상 ──────────────────────────────────── │  ← 눌러서 접기/펴기
│  ┌────────────────────────────────────────────────────────────┐  │
│  │ ● my-site   실행 중            터널 [ON ] [로그] [삭제]     │  │  ← 터널 카드
│  │ ──────────────────────────────────────────────────────────  │  │
│  │   ● 블로그 │ blog.example.com │ http://localhost:3000  [ON] │  │  ← 라우트
│  │   ● api   │ api.example.com  │ http://localhost:8000  [OFF]│  │
│  │   ＋라우트 추가                                             │  │
│  └────────────────────────────────────────────────────────────┘  │
│ ▶ 🖧 webPi  1개 ───────────────────────────────────────────────  │  ← 접힘
│  ┌────────────────────────────────────────────────────────────┐  │
│  │ ● pi-main   중지됨   이 대상에서 실행 불가   터널 [   ]     │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

**기기 카테고리 (접기/펴기)**
터널 목록은 **그 터널을 만든 기기**별로 묶여 표시됩니다. Cloudflare의 터널 목록은 계정 단위라
어느 기기에서 봐도 전부 보이지만, 실제로 실행하려면 그 터널을 만든 기기여야 하기 때문입니다.
지금 보고 있는 대상에는 **현재 대상** 표시가 붙고, **나머지 기기의 그룹은 자동으로 접힙니다**
(어차피 이 대상에서는 실행할 수 없으니까요). 머리글을 누르면 언제든 펴고 접을 수 있고,
대상을 바꾸면 새 대상 기준으로 다시 정리됩니다.

**"이 대상에서 실행 불가"**
그 터널의 자격증명 파일(`~/.cloudflared/<터널ID>.json`)이 이 기기에 없다는 뜻이고, 토글이 잠깁니다.
만든 기기에서 켜거나, 자격증명 파일을 이 기기로 복사하면 됩니다.

**상태 색**
회색=중지, 노랑=시작 중, 초록=실행 중, 빨강=오류. 터널은 큰 동그라미, 라우트는 작은 동그라미입니다.

## 사용법

### 1. 터널 만들기

**＋터널 생성**을 누르면 4단계 마법사가 뜹니다.

| 단계 | 입력 | 설명 |
|---|---|---|
| 1 | 터널 이름 | 목록에서 구분할 이름. 접속 주소와 무관하며 설정 파일 이름에 쓰입니다. 영문·숫자·하이픈·밑줄. |
| 2 | 서브도메인 + 루트 도메인 | 방문자가 입력할 주소. 두 칸을 합친 주소로 CNAME이 자동 생성됩니다. |
| 3 | 로컬 서비스 주소 | 터널이 트래픽을 보낼 곳. 예: `http://localhost:8000` |
| 4 | 서버 실행 방법(선택) | 명령 또는 도커 컴포즈. 비워두면 터널만 만들고 서버는 직접 켭니다. |

**생성 시작**을 누르면 터널 생성 → DNS 등록 → 설정 파일 작성이 차례로 진행되고,
각 단계의 실제 실행 명령이 화면에 표시됩니다. 실패하면 그 자리에서 **되돌리기**로 정리할 수 있습니다.

2단계에서 **"지금은 도메인을 연결하지 않고 터널만 만들기"** 를 고르면 터널만 먼저 만들고
도메인은 나중에 `라우트 추가`로 붙일 수 있습니다. 이 경우 카드에 `라우트 없음` 표시가 뜨는데,
연결된 도메인이 없어 터널을 켜도 404만 응답한다는 뜻입니다.

### 2. 라우트와 서버

- **라우트 추가**: 이미 있는 터널에 서브도메인을 더 붙입니다. 같은 터널을 공유하므로 터널을 새로 만들 필요가 없습니다.
- **서버 등록**: 라우트 오른쪽의 `서버 등록` 버튼으로 시작·정지 명령을 지정하면, 그 다음부터 토글로 서버를 켜고 끌 수 있습니다.
  - **명령**: `uvicorn main:app --port 8000` 같은 실행 명령과 작업 폴더
  - **도커 컴포즈**: 작업 폴더(`docker-compose.yml` 위치)만 있으면 시작·정지 명령은 기본값이 채워집니다
- **터널을 켤 때 함께 시작**을 체크하면 터널 토글 하나로 서버까지 같이 올라옵니다.

> 라우트를 추가·수정한 뒤에는 터널을 껐다 켜야 반영됩니다. 필요하면 앱이 배너로 알려줍니다.

### 3. 켜고 끄기

카드 오른쪽 **터널** 토글이 `cloudflared tunnel run`, 라우트 줄의 **서버** 토글이 그 라우트의 서버입니다.
스피너가 도는 동안은 시작/정지가 진행 중이라는 뜻입니다.

앱을 종료해도 둘 다 계속 실행됩니다. 완전히 끄려면 토글을 내리세요.

### 4. 로그 보기

카드의 **로그** 버튼을 누르면 탭 하나에 터널 로그, 그 뒤로 라우트마다 서버 로그가 열립니다.
실시간으로 따라붙으며, 서버가 왜 안 뜨는지 확인할 때 가장 먼저 볼 곳입니다.

## 원격 기기 관리 (SSH)

상단 **대상** 콤보에서 `SSH 대상 추가...` 를 고르면 프로필을 등록할 수 있습니다.

| 항목 | 예시 | 비고 |
|---|---|---|
| 이름 | `webPi` | 목록에서 구분할 이름 |
| 호스트 | `100.78.119.115` 또는 `webpi` | Tailscale 주소나 LAN IP |
| 포트 | `22` | |
| 사용자 | `admin` | |
| 키 파일 | `C:\Users\사용자\.ssh\id_ed25519` | 비밀번호는 저장하지 않습니다 |

**키 인증만 지원합니다.** 미리 `ssh-copy-id` 등으로 공개키를 대상에 등록해 두세요.
집 밖에서도 접속하려면 [Tailscale](https://tailscale.com) 같은 메시 VPN을 추천합니다 —
포트 포워딩 없이 어디서나 같은 주소로 붙을 수 있습니다. 전체 구축 절차는
[`docs/rpi-selfhost-setup.md`](docs/rpi-selfhost-setup.md) 에 정리돼 있습니다.

대상을 바꾸면 화면 전체가 그 기기 기준으로 다시 그려집니다. 터널 목록, 서버 상태, 프로젝트,
로그 모두 그 기기의 것입니다. 이전 대상에서 돌던 것들은 **계속 실행된 채** 화면에서만 사라집니다.

## 프로젝트 (Git 클론)

**SSH 대상에서만 활성화되는 기능입니다.** 원격 기기에 Git 저장소를 클론하고 목록으로 관리합니다.
내 PC의 프로젝트는 이미 로컬에 있으니 앱이 다시 클론할 이유가 없어서, 로컬 대상에서는 버튼이 잠깁니다.

1. 원격 대상을 선택한 뒤 **프로젝트** 버튼
2. **클론 추가** → Git 주소를 붙여넣으면 이름과 목적지 경로가 자동으로 채워집니다
3. 클론이 끝나면 목록에 상태·경로·커밋 해시가 표시됩니다
4. 이후 각 줄의 **⋮** 메뉴에서 환경설정 · 로그 · 업데이트(`git pull`) · 삭제

클론 위치의 기본값은 `/srv/apps` 이고 **설정 → 프로젝트 클론 위치**에서 바꿀 수 있습니다.
클론한 폴더는 라우트 편집창의 **프로젝트에서 선택** 버튼으로 서버 작업 폴더에 바로 넣을 수 있습니다.

> 클론과 `git pull` 도 백그라운드로 돌고 로그가 남습니다. 큰 저장소를 받는 동안에도 UI는 멈추지 않습니다.

### 환경설정 (.env) — 프로젝트마다 다른 값

`⋮ → 환경설정`은 프로젝트 폴더의 `.env`를 편집합니다. 비밀번호류(`*_PASSWORD`, `*_SECRET`,
`*_TOKEN` 등)는 자동으로 가려서 표시되고, **값 표시**를 켜면 볼 수 있습니다.

맨 위의 **호스트 포트**가 여러 프로젝트를 올릴 때 실제로 바꾸게 되는 값입니다.
`docker-compose.yml`에 이렇게 적어두면 됩니다.

```yaml
ports:
  - "127.0.0.1:${HOST_PORT:-8000}:8000"
```

이러면 두 번째 프로젝트는 `HOST_PORT=8001`, 세 번째는 `8002`처럼 `.env`만 바꾸면 됩니다.
**compose 파일 자체는 건드리지 않으므로 `git pull`과 충돌하지 않습니다** — 앱이 YAML을
다시 쓰지 않는 이유이기도 합니다(주석이 사라지고, 대상 머신에 로컬 수정이 남습니다).

라우트를 만들 때 **프로젝트에서 선택**을 쓰면 그 프로젝트의 `HOST_PORT`를 읽어
로컬 서비스 주소(`http://localhost:8001`)까지 자동으로 채워줍니다.

내 PC에 이미 쓰던 `.env`가 있다면 **파일에서 불러오기**로 그대로 올릴 수 있습니다.
읽어서 화면을 채우기만 하므로, **저장**을 눌러야 대상 머신에 반영됩니다.

> 포트나 환경변수를 바꾼 뒤에는 서버를 껐다 켜야 적용됩니다.

## 자주 겪는 문제

**`code: 1003` — DNS 레코드가 이미 있습니다**
그 주소에 이미 A/AAAA/CNAME 레코드가 있다는 뜻입니다. 예전에 삭제한 터널이 CNAME을 남겨둔 경우가 흔합니다.
마법사가 **기존 DNS 레코드 덮어쓰기** 버튼을 띄워주니 그대로 누르면 됩니다.

**터널 삭제가 "active connection" 오류로 실패합니다**
아직 연결이 정리되지 않은 상태입니다. 잠시 기다렸다 다시 시도하세요.

**"이 대상에서 실행 불가"가 뜹니다**
자격증명 파일이 이 기기에 없습니다. 만든 기기에서 실행하거나, 그 기기의
`~/.cloudflared/<터널ID>.json` 을 이 기기의 같은 위치로 복사하세요.
다만 **같은 터널을 두 기기에서 동시에 켜면** 두 대가 모두 연결되어 요청이 나뉘어 들어갑니다.
기기마다 터널을 따로 만드는 편이 헷갈리지 않습니다.

**클론이 권한 오류로 실패합니다**
클론 위치가 없거나 쓸 수 없는 경우입니다. 대상에서 한 번만 만들어 주세요.

```bash
sudo mkdir -p /srv/apps && sudo chown $USER /srv/apps
```

**"대상과의 연결이 끊겼습니다" 배너**
SSH가 끊긴 상태입니다. 앱은 폴링 주기를 늘려가며 계속 재시도하고, 다시 붙으면 배너가 사라집니다.
원격 프로세스는 그동안에도 멈추지 않습니다.

**도메인에 접속하면 502가 뜹니다**
터널은 떴는데 뒤쪽 서버가 없는 경우입니다. 라우트의 서버 토글과 로그를 확인하세요.

## 데이터가 저장되는 곳

| 무엇 | 어디 |
|---|---|
| 앱 설정 (터널·라우트·SSH 프로필·프로젝트) | `%APPDATA%\CloudflareTunnelGUI\settings.json` |
| 실행 상태(PID)와 로그 | **대상 머신**의 `~/.cloudflare-gui/run/` |
| cloudflared 설정·자격증명 | **대상 머신**의 `~/.cloudflared/` |

SSH 비밀번호는 어디에도 저장하지 않습니다(키 인증만 사용).
실행 상태를 대상 머신의 디스크에 두기 때문에, 앱을 지웠다 다시 깔아도 돌던 프로세스를 다시 찾아냅니다.

## 개발자용

### 구조

```
app/
  core/       # PyQt 의존 없는 순수 로직 (터미널에서 테스트 가능)
    runner.py       # LocalRunner / SshRunner 공통 인터페이스 - 모든 기능이 로컬·원격 양쪽에서 동작하는 이유
    process_mgr.py  # 실행 상태 머신 (PID 파일 기반, GUI가 프로세스를 소유하지 않음)
    cloudflared.py  # cloudflared CLI 래퍼
    config_yml.py   # config-*.yml 읽기/쓰기
    git_repo.py     # 클론 경로 검증, 클론 상태 판정
    store.py        # settings.json 데이터 모델
  ui/         # PyQt6 위젯
```

핵심 규칙 두 가지:

1. `app/core/*` 는 **PyQt6를 import 하지 않습니다.** UI 없이 테스트할 수 있어야 하기 때문입니다.
2. 모든 원격/로컬 동작은 `CommandRunner` 인터페이스를 통과합니다. 기능을 추가할 때 `run()`,
   `spawn_detached()`, 파일 API만 쓰면 SSH에서도 자동으로 동작합니다.
