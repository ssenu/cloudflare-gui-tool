목표

GUI를 껐다 켜도 터널·서버가 유지되고, 터널 하나에 여러 사이트를 붙일 수 있으며, 컨테이너를 서비스로 등록할 수 있게 한다.

전역 제약

  • app/core/*는 PyQt6를 import하지 않는다
  • 모든 명령·파일 조작은 CommandRunner를 경유한다 (UI에서 subprocess 직접 호출 금지)
  • UI 텍스트는 한국어, 이모지 금지 (아이콘은 app/ui/icons.py의 make_icon)
  • 색상은 app/ui/theme.py: current_palette(mode)에서만 가져온다 (하드코딩 금지)
  • 실행 상태 디렉터리: 대상 머신의 ~/.cloudflare-gui/run/
  • 터널 config: ~/.cloudflared/config-<터널명>.yml (유지)
  • 앱 설정: %APPDATA%/CloudflareTunnelGUI/settings.json (유지)
  • 기존 테스트는 계속 통과해야 한다 (마이그레이션 태스크에서 갱신되는 것 제외)

1Runner 분리 실행 · PID · 로그 tailcore

📁 app/core/runner.py, app/core/ssh_runner.py, tests/test_runner_detached.py

CommandRunner에 추가할 추상 메서드:

def spawn_detached(self, cmd: list[str], cwd: str | None, log_path: str) -> int
def pids_alive(self, pids: list[int]) -> set[int]
def kill_pid(self, pid: int) -> None
def tail_file(self, path: str, offset: int) -> tuple[int, str]
def ensure_dir(self, path: str) -> None
def list_dir(self, path: str) -> list[str]
  • spawn_detached: 로그 파일에 append 모드로 stdout/stderr 리다이렉트, PID 반환. 로컬은 DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP + close_fds. 원격은 sh -c 'cd <cwd> && setsid nohup <cmd> >> <log> 2>&1 < /dev/null & echo $!' 후 stdout에서 PID 파싱.
  • pids_alive: 로컬은 ctypes OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION) + GetExitCodeProcess로 STILL_ACTIVE 확인, 실패 시 죽은 것으로 간주. 원격은 한 번의 명령 for p in ...; do kill -0 $p 2>/dev/null && echo $p; done.
  • kill_pid: 로컬 taskkill /PID <pid> /T /F. 원격 kill -TERM -<pid> || kill -TERM <pid>, 1초 후에도 살아있으면 -KILL.
  • tail_file: offset부터 읽어 (새 offset, 텍스트). 파일이 없으면 (0, ""). offset이 파일 크기보다 크면(로테이트됨) 0부터 다시 읽는다. 원격은 SFTP seek/read.
  • ensure_dir: 로컬 os.makedirs(exist_ok=True), 원격 mkdir -p.
  • list_dir: 파일명 목록. 없으면 빈 리스트.

⚠️ 기존 spawn(파이프)은 온보딩의 winget/login 실행에 계속 쓰이므로 남겨둔다.

테스트 (LocalRunner, 실제 프로세스):

  • spawn_detached로 60초 sleep 파이썬 프로세스를 띄우고 → pids_alive에 포함 → kill_pid 후 미포함
  • 출력이 로그 파일에 쌓이고 tail_file이 증분만 반환 (두 번 호출해 두 번째는 새 내용만)
  • 로그 파일 offset이 크기보다 클 때 0부터 재시작
  • ensure_dir/list_dir 동작
  • SSH는 순수 로직(명령 문자열 조립)만 테스트, 실제 연결은 수동 검증

2데이터 모델 v2 + 마이그레이션core

📁 app/core/store.py, tests/test_store.py

스펙의 ServiceSpec/RouteMeta/TunnelMeta 정의를 적용. RouteMeta.id는 secrets.token_hex(4)로 생성하는 헬퍼 new_route_id() 제공.

SettingsStore.load() 마이그레이션:

  • 터널 dict에 routes가 있으면 그대로 파싱 (각 라우트의 server도 dict → ServiceSpec)
  • routes가 없고 hostname/service/server_cmd 중 하나라도 값이 있으면 라우트 1개 생성:
    RouteMeta(id=new_route_id(), hostname=..., service=..., server=ServiceSpec(kind="command", start_cmd=server_cmd, cwd=server_cwd, autostart=start_together))
  • 둘 다 없으면 빈 routes
  • 잘못된 라우트 항목은 개별 스킵 (기존 방어 패턴 유지)
  • 마이그레이션이 일어났으면 load() 반환 전에 save() 호출

save()는 중첩 dataclass를 asdict로 직렬화.

테스트:

  • v1 형식 JSON(hostname/service/server_cmd/start_together) 로드 → 라우트 1개로 변환, autostart 보존, 파일이 새 형식으로 다시 저장됨
  • v2 형식 왕복 (라우트 2개, 도커 서비스 1개 포함)
  • 라우트 배열에 잘못된 항목이 섞여 있어도 나머지는 로드
  • 기존 손상 JSON 방어 테스트는 계속 통과

4RunRegistry + ProcessManager v2core

📁 app/core/run_registry.py (신규), app/core/process_mgr.py (재작성), tests/test_run_registry.py, tests/test_process_mgr.py

RunRegistry(runner) — 대상 머신의 ~/.cloudflare-gui/run/ 관리:

def unit_tunnel(name) -> str                  # "tunnel-<name>"
def unit_service(tunnel, route_id) -> str     # "svc-<tunnel>-<route_id>"
def pid_path(unit) -> str / log_path(unit) -> str
def write_pid(unit, pid) / read_pid(unit) -> int | None / clear_pid(unit)
def rotate_log_if_big(unit, limit=5_000_000)
def known_units() -> list[str]                # run 디렉터리 스캔
def alive_map(units: list[str]) -> dict[str, bool]   # PID 일괄 확인

ProcessManager(runner_provider) 재작성 — 메모리 핸들 대신 레지스트리를 읽는다:

def start_tunnel(name, client)            # spawn_detached(client.run_args(name)) → write_pid
def stop_tunnel(name)                     # kill_pid → clear_pid
def tunnel_state(name) -> TunnelState     # 스펙의 판정 표
def start_service(tunnel, route)          # kind별 분기
def stop_service(tunnel, route)
def service_running(tunnel, route) -> bool
def refresh(tunnels: list[TunnelMeta])    # 폴링 1회: PID 일괄 확인 + 도커 상태 조회 결과를 캐시
def log_path_for_tunnel(name) / log_path_for_service(tunnel, route)
  • 상태 판정은 refresh()가 채운 캐시를 읽는다(UI가 1초마다 refresh() 호출, 개별 조회는 캐시 히트).
  • 터널 RUNNING 판정: PID 생존 + 로그 마커. 마커 탐색은 tail_file로 읽어들인 누적 텍스트에서 확인하고, 시작 시점 이후만 보도록 시작할 때 오프셋을 기록한다.
  • 도커 서비스: docker compose ps -q를 cwd에서 실행, 출력이 비어있지 않으면 실행 중. 명령 실패(도커 미설치 등)는 "중지"로 간주하고 사유를 로그 파일에 남긴다.
  • 명령 서비스 정지: stop_cmd가 있으면 그것을 실행, 없으면 kill_pid.
  • StatusTracker(메모리 상태 기계)는 제거한다. LogBuffer도 파일 tail로 대체되므로 제거하고 뷰어가 오프셋을 관리한다.

테스트 (FakeRunner로 파일 시스템과 PID를 시뮬레이션):

  • 판정 표 4분기(PID 없음/생존+마커/생존+마커없음/죽음) 각각
  • 정지 시 PID 파일 삭제, 이후 상태는 STOPPED (ERROR 아님)
  • 도커 서비스: ps -q 출력 유무에 따른 판정, 명령 실패 시 중지 처리
  • refresh()가 PID 조회를 단위 수와 무관하게 1회만 호출하는지 (FakeRunner 호출 카운트)
  • 서로 다른 러너로 시작한 상태가 섞이지 않는지 — 레지스트리가 대상별로 분리되므로 러너 교체 후 refresh() 결과가 새 대상 기준인지

6터널 카드 재구성ui

📁 app/ui/main_window.py
  • 카드 = 헤더(상태등 + 터널명 + 상태 텍스트 + 터널 토글 + 로그 + ⋮) + 라우트 행 목록 + "라우트 추가" 버튼.
  • 라우트 행: hostname → 서비스 주소, 서버 토글(서비스 미등록이면 "서버 등록" 버튼), 로그 버튼, ⋮(편집/삭제).
  • 터널 토글 ON: start_tunnel 후 autostart인 서비스들을 start_service. OFF: 터널만 정지(서비스는 그대로 둔다 — 독립 토글이므로).
  • 1초 폴링은 manager.refresh(터널목록) 1회 → 각 위젯이 캐시된 상태로 표시 갱신. 토글은 사용자가 조작 중일 때 신호 루프가 생기지 않도록 blockSignals로 상태만 반영.
  • ⋮ 메뉴의 삭제는 danger_menu_action 사용. 삭제 확인 다이얼로그의 삭제 버튼도 danger 색.
  • 터널 삭제 시 모든 라우트의 서비스와 터널을 먼저 정지하고 PID 파일을 정리한다.
